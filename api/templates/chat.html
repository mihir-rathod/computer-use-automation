Capability Chatbot

A thin front door over the capability API -- GET /capabilities / POST /capabilities/{id}/invoke. Each message is evaluated fresh; try something self-contained, e.g. "look up the balance for meridian member 100987" or "transfer $5 from 100987-S0001 to 100987-MMKT-5 for member 100987".

If a request needs a human (an irreversible action, or something that got stuck), it pauses here -- keep the operator console open in another tab to catch it.

Required fields per capability -- include all of them, every time
CapabilityRequired fields
Balance inquirymember_id
Funds transfermember_id, from_share, to_share, amount
Open sharemember_id, share_type, initial_deposit
Update membermember_id, email, phone, address -- all four, even to change just one
Place holdmember_id, share, reason_code

A message missing a required field gets declined with a plain-text reply asking for it, instead of silently running the wrong capability.
